# Stage 5 test plan

| Layer               | Cases and expected outcome                                                                                                                                                                            | Command                                               |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| Shared contracts    | Reject malformed IDs, sizes, file names, search terms, duplicate attachment IDs and unknown sensitive fields                                                                                          | `npm test`                                            |
| API policy          | Reciprocal direct keys, immutable owner role, canonical fingerprints, seek cursor validation and byte validation                                                                                      | `npm test`                                            |
| API HTTP            | Existing versioned health endpoints and safe error envelopes                                                                                                                                          | `npm run test:api`                                    |
| MongoDB replica set | Reciprocal direct creation, atomic group creation, removal and rejoin authorization, concurrent sends, changed payload conflict, repeated deletion, scoped text search and equal-timestamp pagination | `npm run test:db`                                     |
| Private object API  | Upload completeness, signature enforcement, private reads, ownership, conversation scope, membership removal, deletion and downloaded byte equality                                                   | `npm run test:db` with `CHATAPP_TEST_S3_*` configured |
| Mobile services     | Current bearer and origin, redirects, retry preservation, canonical confirmed message rows, discovery, group requests, attachment cancellation, search and deletion responses                         | `npm test`                                            |
| Mobile builds       | Expo compatibility, route validation, Android/iOS export and storage-secret canary checks                                                                                                             | See [evidence](TEST_EVIDENCE.md)                      |
| Devices             | Two real accounts, native photo/PDF pick, cancel, progress, preview/share, deletion prompt and backend switch regression                                                                              | [Demonstration walkthrough](DEMONSTRATION_GUIDE.md)   |

Integration setup requires an elected MongoDB primary at a loopback `chatapp_test` origin. Each test uses a randomly named database and drops it afterward. The storage test can use an independent bucket on a local VersityGW instance and removes it afterward. Without the test S3 environment, attachment domain tests substitute a deterministic in-process storage service. CI supplies the real service and random credentials.

For a local full stack, start the Compose services described in [Stage 5 implementation](STAGE_5_IMPLEMENTATION.md). Export `CHATAPP_TEST_DATABASE_URL`, `CHATAPP_TEST_S3_ENDPOINT`, `CHATAPP_TEST_S3_ACCESS_KEY_ID` and `CHATAPP_TEST_S3_SECRET_ACCESS_KEY` from the local setup before invoking the test command. Keep the API test signing key and database isolated from developer data.
