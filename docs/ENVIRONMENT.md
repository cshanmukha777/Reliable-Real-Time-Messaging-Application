# Environment configuration

Copy `.env.example` to `.env` at the workspace root for the API. Copy `apps/mobile/.env.example` to `apps/mobile/.env.local` for Expo. The two files are ignored by Git. Deployment systems should inject API configuration at runtime and provide only public Expo variables at build time.

| Variable                       | Location              | Meaning                                                                                                                                                                                                                                             |
| ------------------------------ | --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DATABASE_URL`                 | API only              | Prisma MongoDB URI, with an explicit database name. Required. Template points to the loopback-only local replica set without credentials. Use an authenticated, TLS-enabled URI for deployment.                                                     |
| `HOST`                         | API only              | Bind address. Defaults to `127.0.0.1`. Set `0.0.0.0` temporarily to give a physical device on the same trusted LAN access.                                                                                                                          |
| `PORT`                         | API only              | TCP port from 1 to 65535. Defaults to 3000.                                                                                                                                                                                                         |
| `NODE_ENV`                     | API only              | `development`, `test`, or `production`. Defaults to development. Invalid values fail at startup.                                                                                                                                                    |
| `CORS_ORIGINS`                 | API only              | Comma-separated explicit browser origins. Empty disables cross-origin headers. Production origins require HTTPS. Native Expo requests do not depend on browser CORS.                                                                                |
| `EXPO_PUBLIC_API_BASE_URL`     | Expo                  | Public HTTP(S) origin, such as `https://api.example.com` or an explicitly enabled development address. The app adds `/v1`. Credentials, query parameters and paths are rejected.                                                                    |
| `EXPO_PUBLIC_ALLOW_LOCAL_HTTP` | Expo                  | Defaults to false. The app permits HTTP only when this is exactly `true`, JavaScript is a development bundle and the origin is loopback or a private IPv4 literal. For release builds, leave this false during native prebuild as well as bundling. |
| `CHATAPP_TEST_DATABASE_URL`    | Test shell or CI only | Dedicated local replica-set URI with path `/chatapp_test`. Each test suite generates its own isolated database suffix.                                                                                                                              |

API startup errors list invalid variable names. Readiness responses contain no configuration values. The API defaults MongoDB connection and server-selection timeouts to 2000 ms unless specified in the URI.

The Settings screen tests an origin before activating an override. Reset to the build-time origin requires confirmation. A saved HTTP origin becomes incompatible with a release bundle. The shell shows a message when that happens. Only the backend origin, appearance preference and diagnostic probe metadata are stored in SQLite.

Stage 2 uses HTTPS for release HTTP traffic. Future WebSocket clients must derive WSS from the HTTPS origin. The public Expo environment must never contain database, Prisma, signing, or authentication credentials. The CI export job injects an inert server-only canary and the security job searches both bundles for it.
